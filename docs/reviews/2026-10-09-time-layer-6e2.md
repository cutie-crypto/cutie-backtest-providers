起点：`origin/main b42210ba1f47a2dcd98c9e2abbf9a0754088a5e5`；独立分支 `feat/1009-cx3-time-6e2`，无上游跟踪。第一段 F1 修复在另一条分支，已推送 `e698d26`；本分支没有夹带 F1/F2 代码。

## 新键和拒绝契约

| 键值 | 类型 / 默认 | 必须同时满足 |
| --- | --- | --- |
| `time_calendar=none` | string / `none` | 不新增日历门禁或 assumptions；省略、显式 none 的关闭结果字节相同 |
| `us_equity_regular` | string / 枚举 | `time_layer_enabled=true`，`time_timezone=America/New_York`，固定周期 <1d |
| `cme_btc_regular` | string / 枚举 | `time_layer_enabled=true`，`time_timezone=America/Chicago`，固定周期 <1d |

非字符串、未知枚举、错时区、开关关闭、周期 ≥1d 均取数前 `INVALID_PARAMS`。日历沿现有 schema 合并循环发布到 22 个单仓工具和 3 个账本工具；3 个 kernel_v3、1 个海龟工具不声明新键。海龟原有共享持仓根数例外保持不变。

单仓与账本原有调用都把当前根收盘边界交给 `TimeContext.allow_entry`；它同时是行情连续时预计次根成交开盘。新检查使用 `RegularCalendar.contains_bar`，要求从此开盘到其收盘的整根 K 线落在交易时段内，再与旧时段/星期过滤相交。每次账本买入（含加仓）同样检查。退出路径不调用此门禁。保留全部连续行情、不裁行情、不读取未来价格。

启用时只在 `assumptions.time_layer.calendar` 写入日历名、`entire_next_fill_bar` 与 `REGULAR_CALENDAR_ASSUMPTION` 原文。result.v2 逐笔、权益、metrics、manifest 键集不变。

## 独立验收序列

`backtesting-py/tests/test_time_layer_6e2.py` 的常量 UTC 序列与会话边界均人工由当地时钟换算，不调用被测日历生成期望：
- 美股周末：周五 20:30Z 及下周一 14:30Z 成交；周五 21:00Z、周六拒绝。
- 美股 DST：2026-03-08 周日及跳时前后不开仓；周一首次 09:30 EDT = 13:30Z，可由闭市信号根提交。
- CME 日间暂停：15:30 CST = 21:30Z 可成交，16:00–17:00 CST 暂停；17:00 CST = 23:00Z 恢复。
- CME 周末和 DST：周五 21:30Z 可成交；周五晚、周六、DST 周日凌晨拒绝；周日 17:00 CDT = 22:00Z 恢复。

四序列各走真实单仓 Backtest 和 Decimal 账本；实际注册 EMA / RSI 分批 / 网格 / DCA HTTP 路由另各四例。单仓、账本各证明 15:00 当地的 1h 开仓可成交，16:00 闭市仍正常到期退出；15:30 起的整根 1h K 线跨收盘即拒绝。CME 暂停期已有仓位的两次加仓被拒，恢复后加仓成功；日历同时与时段和星期相交。

codex-3 定：DCA 每日信号仍在当地午夜触发；美股常规日历与之取交集会拦住该日开仓，不把信号挪到开市，不引入新的补单语义。CME 午夜在常规交易时段内时可开仓。测试明确断言美股 DCA 四序列中的两条路由为零交易，其余注册路由均产生交易并核对独立 UTC 会话边界。
